# media-transcriber v1 — task breakdown

Spec (single source of truth): `docs/superpowers/specs/2026-07-27-media-transcriber-design.md`. Each task cites the spec sections that bind it; exact values (event shapes, timeouts, schema) live there. Research references: `docs/research/`.

## Global Constraints

- macOS 26.5, Swift 6.3 (helper), Node 22+/TypeScript strict (server). Repo layout per spec §1.
- Helper NDJSON contract exactly as spec §4; transcript schema exactly as spec §3; timeouts/progress exactly as spec §6.
- Fastify binds loopback only (spec §1). Serial job queue, concurrency 1 (spec §5).
- Diarization failures degrade, never fail jobs (spec §8). FluidAudio pinned v0.15.5.
- No features beyond the spec (YAGNI). Tests per spec §7.

## Task 1: Swift helper — transcription core

Create `helper/` SPM executable `speech-helper` (deps: swift-argument-parser only, for now). Implement spec §4 minus diarization: `status` command; `transcribe --input --locale [--no-diarize]` emitting `ready` (with durationSec), `model_download`, `progress` (stage transcribe), `segment`, `done`, `error` NDJSON events; locale normalization via `supportedLocale(equivalentTo:)` + BCP-47 compare; idempotent `assetInstallationRequest`; `AVAudioFile` → `analyzeSequence(from:)` → `finalizeAndFinish(through:)` with results task started first; sentence segmentation via NaturalLanguage with `.audioTimeRange` per sentence; MP3 tail-probe/repair producing one prepared URL used by all stages, cleaned up at exit (spec §4 items 1–6). Map SFSpeechError to error codes (spec §6). Acceptance: `swift build -c release`; `status` prints JSON; transcribing a `say`-generated AIFF and the repo's known-good mp4 fixture produces correct events; no-audio mp4 → clean `error` event, nonzero exit. Reference implementations: `docs/research/2026-07-27-github-oss-research.md` §1a–1b (yap is CC0 — copying its sequences is encouraged).

## Task 2: Swift helper — speaker identification

Add FluidAudio v0.15.5 (exact) dependency. Implement spec §4 items 7–8 and §8: post-transcription diarization of the prepared URL (decode to 16 kHz mono Float32 via AVAudioConverter `primeMethod = .none`), `OfflineDiarizerManager` → `speakers` event (S1/S2 by first appearance), `progress` stage diarize, `warning` event `diarizationFailed` on any diarization error with job still completing, `--no-diarize` skips entirely. Acceptance: two-voice `say` fixture yields 2 speakers; `--no-diarize` emits no diarize-stage events; simulated model failure (e.g. offline env var pointing at unreachable registry) yields warning + successful transcript. Reference: `docs/research/2026-07-27-fluidaudio-notes.md`.

## Task 3: TypeScript server — jobs, queue, helper supervision

Create `server/` (Fastify, TypeScript strict, zod, vitest; Node 22). Implement spec §2 POST /jobs + GET /jobs + GET /jobs/:id, §5 disk job store (`data/jobs/<id>/job.json`, nanoid-style ids, restart marks stale queued/running as interrupted), FIFO queue concurrency 1, helper spawn with NDJSON parsing, the three timeouts and monotonic progress mapping of §6, warnings[] persistence, stderr capture. Loopback-only listen (§1). Fake-helper (shell script) unit tests for queue, timeouts, progress, warnings, restart recovery. Acceptance: vitest green; manual curl round-trip against fake helper.

## Task 4: TypeScript server — transcript assembly, SRT, health

Implement transcript.json assembly per spec §3 (merge `speakers` turns onto sentence segments by max overlap — server-side merge using helper events; `metadata.diarization`/`speakerCount`; millisecond rounding), SRT renderer (`HH:MM:SS,mmm`, yap-style sentence blocks), GET transcript.json/.srt routes, `/health` (helper present, `status` output, installed locales). Unit tests: merge logic (incl. no-overlap → null), SRT golden file, health degraded when helper missing. Acceptance: vitest green.

## Task 5: E2E smoke tests, fixtures, README

`scripts/make-fixtures.sh` generating single-voice and two-voice `say` fixtures (aiff/m4a); E2E test (macOS, real helper): POST fixture → poll → assert transcript text, speaker count 2 on two-voice, SRT present; document known-good mp4 fixture usage. README.md: what it is, requirements (macOS 26+), build (`swift build -c release`, `npm i`), run, API examples, links to spec/research. Acceptance: E2E passes locally end-to-end; README commands verified by running them.
